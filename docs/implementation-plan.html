02

How it fits together

One TypeScript repository. Two processes: the website handles people; the worker collects messages and writes summaries.

01TelegramGramJS reads
02PostgresMessages + jobs
03Gemini CLIYour Pro login
04PostgresPosts + questions
05WebsiteDiscover + edit

↳ An author’s answer saves immediately and queues a suggested revision.

React + TanStack + Vite

React draws screens. Start provides the server and Router; Query caches data; Form handles inputs. Vite builds the app.

Effect v4

Runs application operations and handles failures, timeouts and resources. Effect Schema validates inputs and model output.

PostgreSQL + @effect/sql-pg

Stores messages, people, posts, comments and jobs. The SQL package connects Effect to the database.

pg-boss

Remembers which work is pending across restarts. Owns job retries; Effect runs each attempt.

GramJS

Reads the configured group through your Telegram account. Website users have their own, separate login.

Gemini CLI + Google Pro

Uses your subscription login. Verify Gemini 3.8 Flash in task 03; no API-credit fallback.

Telegram + X login

Telegram proves post ownership. X-only visitors can comment. Auth.js stays provisional until task 04.

Railway, proposed

Runs the website, the persistent worker and Postgres. Protected login sessions and scheduled backups.

Collection keeps running when the model waits. Messages, jobs and collection progress save in one transaction. Quota limits pause model work without stopping ingestion.
